# Working style

1. Don't assume. Clear up assumptions before acting, surface trade-offs.
2. For key decisions, say how a senior engineer would decide, compare with the current plan, and state it before proceeding.
3. Short comments only.
4. No duplicated code; use strategy pattern and dependency injection where they fit.
5. Concise summary at each milestone.
6. Keep the codebase organized; no clutter.
