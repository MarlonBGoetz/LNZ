# Kiro × Runpod GPU Supervisor — Build Plan

Oct 24, 2026 · @Someone

## Goal

Build a Kiro Power called **gpu-overwatch** that lets Kiro launch, watch, fix and shut down Runpod GPU work as if the GPUs were local. Kiro itself writes the code from this plan as a spec, which keeps the project inside the "purely Kiro" rule.

It covers two jobs:

- **Training runs:** one or a few long-lived Pods, supervised for hours, restarted from checkpoint when they fail.
- **Aggressive inference for dataset collection:** many short GPU calls fanned out over Serverless, retried, deduplicated and written as shards.

## Design principles

- **Purely Kiro.** Everything is generated by Kiro from this plan. The plan is the spec and is checked in at `docs/overwatch-plan.md`.
- **Offline-testable.** The whole testable surface runs on the Python standard library only. No network, no GPU, no package installs are required to run `pytest -q tests/`. Real integrations (FastMCP, httpx, the runpod SDK, `npx @runpod/mcp-server`) are declared in config and import-guarded so importing the testable modules never fails when those libraries are absent.
- **Safety first.** Spend caps in `.overwatch/policy.yaml` can only ever be **lowered** by tools, never raised. `state.json` holds per-run bearer tokens and is gitignored and listed in `.kiroignore`.
- **Everything is a run.** Every Pod name is prefixed `ow-<run>` and carries `OVERWATCH_RUN` / `OVERWATCH_KEEP` env vars.

## MCP tools (20, names preserved exactly)

Every tool returns compact JSON plus a one-line human summary.

1. `gpu_recommend` — recommend a GPU type/count given a model+batch estimate.
2. `run_smoke` — launch a short smoke run to validate the image and config.
3. `run_launch` — provision a Pod and start a supervised training run.
4. `run_status` — current status of one run.
5. `run_logs` — tail logs for a run.
6. `run_metrics` — latest metrics (loss, util, step rate) for a run.
7. `run_signal` — send a signal (checkpoint, stop, restart) to a run.
8. `run_restart` — restart a run from its latest checkpoint.
9. `run_stop` — stop a run and optionally keep/destroy the Pod.
10. `run_list` — list known runs.
11. `run_report` — write a Markdown report for a run to `.overwatch/reports/`.
12. `fleet_status` — status across all live Pods.
13. `fleet_reap` — stop/destroy orphaned or over-budget Pods.
14. `budget_status` — current session and per-run spend vs caps.
15. `budget_set` — **lower** a cap (raising is rejected).
16. `artifacts_pull` — pull checkpoints/artifacts from a run's volume.
17. `datagen_start` — start a dataset-generation fan-out.
18. `datagen_status` — progress of a datagen job (shards, records, failures).
19. `datagen_sample` — sample a few generated records.
20. `datagen_stop` — stop a datagen job.

## Sidecar

A per-Pod HTTP service wrapping the training process.

- Endpoints `/status` `/logs` `/metrics` `/signal` behind a per-run bearer token.
- Reflexes: periodic checkpoint, checkpoint on SIGTERM, self-stop at budget/max-hours.

## Command-watch contract (watch.py)

- Read a cursor + config JSON object on **stdin**.
- Print exactly **one** JSON result line: one of `idle`, `new-activity`, or `terminal-state`, each carrying an updated `cursor`.
- Exit `0`.
- The run id travels via the `runId` config key (it is **not** templated into the command).

## Supervision loop (detector thresholds)

Thresholds live in `.overwatch/policy.yaml` and are explained in `gpu-policy.md`.

| Condition | Default | Action |
|-----------|---------|--------|
| NaN loss | restart at half LR, max 2 retries | `run_restart` |
| Divergence | loss EMA rising for 200 steps | alert / restart |
| OOM | halve micro-batch | `run_restart` with smaller batch |
| Stall | no step for 10 min OR util < 5% for 10 min | alert / restart |
| Preemption | 3 missed polls | re-provision |
| Eval regression | eval worse for 3 evals | alert |
| Budget | warn at 80%, stop at 100% | `run_stop` |
| Checkpoint | every 15 min | periodic checkpoint |

## Datagen

- Idempotent record keys = `hash(input, model, template, sampling)`.
- Atomic write-then-rename shards; a manifest lists finished shards.
- Retries with exponential backoff; a poison queue `failed.jsonl`.
- Exact dedup by key.

## Hooks (triggers preserved exactly)

- `SessionStart` — load policy, print a brief.
- `PreToolUse` — guard risky GPU actions against policy.
- `PostToolUse` — record spend and state after each tool.
- `PostFileSave` — re-run relevant checks on config edits.
- `Stop` — graceful checkpoint/stop on session stop.
- `SessionEnd` — reap orphaned Pods, write a session report.

The PostTaskExecution hook runs `pytest -q tests/`.

## Agents

- `.kiro/agents/gpu-medic.json` — triage agent that diagnoses failing runs.
- `.kiro/agents/gpu-operator.md` — operator persona for launching/teardown.

## Workflows

### supervise-run.workflow.json

```json
{
  "name": "supervise-run",
  "description": "Launch, watch, auto-heal and report a Runpod training run.",
  "trigger": "manual",
  "inputs": {
    "config": { "type": "string", "description": "Path to the run config" },
    "gpu": { "type": "string", "description": "GPU type override", "required": false }
  },
  "steps": [
    { "id": "preflight", "tool": "run_smoke", "with": { "config": "${inputs.config}" } },
    { "id": "launch", "tool": "run_launch", "with": { "config": "${inputs.config}", "gpu": "${inputs.gpu}" } },
    {
      "id": "watch",
      "watch": {
        "command": "python -m overwatch.watch",
        "config": { "runId": "${steps.launch.run_id}" },
        "interval": "30s"
      },
      "on": {
        "new-activity": [{ "tool": "run_metrics", "with": { "run_id": "${steps.launch.run_id}" } }],
        "terminal-state": [{ "tool": "run_report", "with": { "run_id": "${steps.launch.run_id}" } }]
      }
    },
    { "id": "report", "tool": "run_report", "with": { "run_id": "${steps.launch.run_id}" } },
    { "id": "teardown", "tool": "run_stop", "with": { "run_id": "${steps.launch.run_id}", "keep": false } }
  ]
}
```

## Build order (phases 0–5)

- **Phase 0** — Scaffold and offline-safe foundation: directory tree, git, `pyproject.toml`, ignore files, the exported plan, and the stdlib-only foundation modules (`config.py`, `state.py`, `policy.py`) with a green pytest harness.
- **Phase 1** — Detectors and the training client (`detectors.py`, `client.py`).
- **Phase 2** — Sidecar HTTP service and signals.
- **Phase 3** — Watch program and guard.
- **Phase 4** — MCP server tools, CLI/doctor/init.
- **Phase 5** — Datagen driver, Power wiring (plugin.json, mcp.json, skills), Kiro steering/hooks/agents/workflows.

## Out of scope for the sandbox

Live Runpod actions (provisioning Pods, real smoke/chaos tests on GPUs, installing the Power in the IDE, toggling Workflows) are documented, not executed. No GPU is present; all detector tests run on CPU via `tests/fake_train.py` with failure injection `--fail nan@300`, `oom@100`, `hang@200`, `crash@50`.
